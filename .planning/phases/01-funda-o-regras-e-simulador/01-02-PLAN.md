<task type="auto">
  <name>Task 1: Instalar o Android SDK, configurar JDK e o Godot para exportar Android</name>
  <files>(fora do repositório) %LOCALAPPDATA%\Android\Sdk, editor_settings-4.7.tres do Godot</files>
  <read_first>
    - .planning/phases/01-funda-o-regras-e-simulador/01-RESEARCH.md (Pitfall 6 e Standard Stack: lista exata do SDK)
    - CLAUDE.md (Exportação Android; Android SDK; OpenJDK 17 recomendado)
  </read_first>
  <action>
Conferir `java -version` (JDK 21 presente; a doc recomenda 17, que só deve ser instalado — Temurin 17 — se a exportação falhar) e definir JAVA_HOME (usuário) para a pasta do JDK. Baixar de developer.android.com/studio (seção "Command line tools only") o zip commandlinetools-win para uma pasta nova e vazia e extrair para %LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest\. Aceitar as licenças (`sdkmanager --sdk_root=... --licenses` respondendo y) e instalar exatamente: "platform-tools", "build-tools;35.0.1", "platforms;android-35", "cmake;3.10.2.4988404", "ndk;28.1.13356709". Definir ANDROID_HOME (usuário) para a pasta Sdk. Configurar o Godot: após rodar `$GODOT_BIN --headless --editor --quit --path .` uma vez para gerar %APPDATA%\Godot\editor_settings-4.7.tres, gravar nele export/android/android_sdk_path e export/android/java_sdk_path (ou confirmar que o Godot assume ANDROID_HOME/JAVA_HOME). Nada disto entra no repositório.
  </action>
  <verify>
    <automated>powershell -NoProfile -Command "& \"$env:ANDROID_HOME\platform-tools\adb.exe\" version; & \"$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat\" --list_installed"</automated>
  </verify>
  <acceptance_criteria>
    - `adb version` imprime `Android Debug Bridge version` e a versão do platform-tools é >= 35.0.0
    - `sdkmanager --list_installed` lista `build-tools;35.0.1`, `platforms;android-35`, `cmake;3.10.2.4988404` e `ndk;28.1.13356709`
    - editor_settings-4.7.tres contém `export/android/android_sdk_path` apontando para a pasta Sdk (ou o SUMMARY registra que o Godot usou ANDROID_HOME)
    - `git status --porcelain` não lista nada novo fora de arquivos do projeto
  </acceptance_criteria>
  <done>SDK, NDK, JDK e Godot configurados; adb disponível.</done>
</task>

<task type="auto">
  <name>Task 3: Keystore de depuração fora do Git, preset Android, exportar e instalar o APK</name>
  <files>export_presets.cfg</files>
  <read_first>
    - export_presets.cfg (preset Windows já existente; acrescentar o Android sem alterar o Windows)
    - .planning/phases/01-funda-o-regras-e-simulador/01-RESEARCH.md (Pitfall 6: keystore de depuração compartilhado, permissions/internet, arquiteturas, A4)
    - O ABI do aparelho registrado na Task 2 (saída de adb shell getprop ro.product.cpu.abi)
  </read_first>
  <action>
1) Gerar com keytool um keystore de depuração em %USERPROFILE%\.cofremagico\debug.keystore (alias androiddebugkey, RSA, validade 9999 dias, DN "CN=Android Debug,O=Android,C=US") — FORA do repositório. Definir variáveis de ambiente de usuário GODOT_ANDROID_KEYSTORE_DEBUG_PATH, GODOT_ANDROID_KEYSTORE_DEBUG_USER e GODOT_ANDROID_KEYSTORE_DEBUG_PASSWORD; registrar no SUMMARY que o colega deve receber o arquivo por canal privado para os dois assinarem com a mesma chave (evita o erro "Could not install to device").
2) Acrescentar ao export_presets.cfg o preset "Android" (platform "Android", export_path build/android/CofreMagico.apk, gradle_build/use_gradle_build = false, permissions/internet = false, package/unique_name com.cofremagico.jogo, architectures/arm64-v8a = true e architectures/armeabi-v7a = true somente se o ABI da Task 2 for 32 bits, min SDK e demais opções conforme o padrão do editor 4.7.2 — registrar no SUMMARY os valores padrão de min SDK e arquiteturas encontrados, que a pesquisa deixou em aberto). Nenhum caminho de keystore nem senha no arquivo.
3) Exportar com `--export-debug "Android" build/android/CofreMagico.apk`. Verificar as permissões do APK com aapt2 (build-tools 35.0.1: `aapt2 dump permissions`). Se a permissão INTERNET aparecer por ser build de depuração, tentar `--export-release` usando o mesmo keystore como keystore de release via variáveis GODOT_ANDROID_KEYSTORE_RELEASE_* (apenas para este APK de teste) e registrar no SUMMARY qual modo produz um APK sem INTERNET, para a Fase 4.
4) Instalar com `adb install -r build/android/CofreMagico.apk` e abrir com `adb shell monkey -p com.cofremagico.jogo -c android.intent.category.LAUNCHER 1`; capturar `adb logcat -d -s godot` e procurar a linha COFRE_MAGICO_INICIAL tamanho_mao=5.
  </action>
  <verify>
    <automated>powershell -NoProfile -Command "& $env:GODOT_BIN --headless --path . --export-debug 'Android' build/android/CofreMagico.apk; & \"$env:ANDROID_HOME\build-tools\35.0.1\aapt2.exe\" dump permissions build/android/CofreMagico.apk"</automated>
  </verify>
  <acceptance_criteria>
    - build/android/CofreMagico.apk existe e a exportação termina com código 0
    - A saída de `aapt2 dump permissions` NÃO contém `android.permission.INTERNET` no APK final escolhido (ou o SUMMARY documenta o modo de exportação que a omite)
    - `adb install -r build/android/CofreMagico.apk` imprime `Success`
    - `adb logcat -d -s godot` contém `COFRE_MAGICO_INICIAL tamanho_mao=5`
    - `grep -ci 'keystore_password\|debug_password\|\.keystore' export_presets.cfg` retorna 0 e `git ls-files | grep -c 'keystore\|\.apk'` retorna 0
    - `grep -E 'use_gradle_build=false|permissions/internet=false' export_presets.cfg` retorna 2 linhas no preset Android
  </acceptance_criteria>
  <done>APK de depuração assinado com keystore externo, sem INTERNET, instalado e iniciado no aparelho.</done>
